# Linux 版使用报告

这份报告记录 Linux 版从源码到打包的实测情况，供决定是否继续做 Windows 版参考。

测试日期：2026 年 9 月
测试环境：Ubuntu 系，Linux 6.8，Python 3.13.15，x86_64

## 一、结论

Linux 版功能完整可用，可以发布。核心链路全部实测通过：
从视频提取原文、逐句人工翻译、导出 Word、导出软字幕、烧录硬字幕，
以及打包成可执行文件后脱离 Python 环境运行。

打包产物在无 Python 的路径下自检全部就绪，语音识别、OCR、PDF、
Word 导出均正常。可以按原计划先发布 Linux 版，再着手 Windows 版。

## 二、功能实测

### 环境自检

源码环境与打包产物都跑过自检，九项全部就绪：
ffmpeg、ffprobe、PySide6、OCR 引擎、语音识别、PDF、Word 导出。

### 从视频提取原文

用一段 12 秒、带英文语音的视频测试，模型选 small。

结果：正确识别出 3 句英文，语言判定为 en，带时间轴。
换 tiny 模型再测，识别出 4 句，句子切分更碎但内容正确。
这说明模型档位确实影响切分粒度，正式使用建议 medium 以上。

### 屏幕取词

用一张模拟新闻页面的图片测试。

全屏识别：走通，识别出全部文字并按行拆句。
手动框选：走通，只识别框内内容，框外文字未被带入。
框选坐标换算经过专门测试，正向拖拽和反向拖拽都能收敛成同一矩形，
点一下不拖会视为取消而不是选出小框。

### 逐句翻译

用浮窗逐句输入译文，验证了三件事：

输入回车后自动跳到下一句，进度从 1/3 走到 3/3。
全部译完后浮窗提示全部完成，仍可回看修改任意一句。
关闭浮窗后重新载入，进度和译文都在，落盘正常。

会话有个设计要点：打开项目时从第一句未译的开始，
所以如果只有第一句译好了，浮窗会直接停在第二句，而不是从头开始。
全部译完则停在首句供回看。

### 导出 Word

导出带原文与译文的对照文档，3/3 句已译时正确标注。
PDF 内嵌图片会随文档导出，按原位置放回。

### 导出软字幕

生成 srt 和 ass 两个文件。
srt 是中英双语，每句一行英文一行中文，时间码正确。
ass 里英文和中文分别定义样式，默认英文白字在上、中文黄字在下，
离底边距离不同，避免两行贴在一起。

### 烧录硬字幕

把双语字幕烧进视频画面。为确认字幕真的画上去了，
抽帧后用 OCR 反查画面底部，识别出英文行和中文行，
证明字幕确实渲染到了画面里，不是只写进了文件。

### 打包成可执行文件

用 PyInstaller 打包，产物约 827 MB。
在打包目录下直接运行，自检全部就绪，
视频提取、字幕导出、字幕烧录三条链路都跑通。

体积偏大的原因是语音识别和 OCR 的底层库本身就不小：
OpenCV 约 187 MB，语音识别运行时约 190 MB，OCR 运行时约 58 MB，
PDF 库约 53 MB。这些是功能必需，没有水分可挤。

## 三、测试覆盖

自动化测试共 110 项，全部通过。分七层：

内核与持久化、会话与导航、OCR 与语音识别、导出、
界面控件与状态、后台任务与框选、设置项与默认行为。

界面测试在无显示环境下用 offscreen 模式运行，
后台任务测试跑的是真实的语音识别和字幕烧录，不是模拟。

## 四、已知限制

屏幕取词目前是手动框选或整屏识别，没有自动版式分析。
网页和 PDF 排版差异大，自动找正文容易出错，先用手动方式更稳妥。
这个功能按原计划等使用的人多了再考虑。

Wayland 桌面下程序无法直接抓屏，这是系统安全限制，
不是程序缺陷。界面上会给出提示，引导用户改用系统截图工具截图后导入。

语音识别对音乐、多人抢话、重口音的音频效果有限，
纯语音单人讲述的材料效果最好。

硬字幕烧录需要重新编码，长视频耗时较久，画质有轻微损失。
只要字幕不要重编码就用软字幕。

语音识别模型不打进安装包，首次使用某个档位需要联网下载一次。
这样做的目的是把安装包体积控制在可接受范围。

## 五、打包时踩到的坑

记录在这里，做 Windows 版时会遇到类似问题。

语音识别库在包初始化时就导入 PyAV，即使程序自己绕开它、
改用外部 ffmpeg 解码音频，这个依赖也不能从打包里排除，
否则一导入就报模块不存在。曾试图排除以省下约 100 MB，失败后已恢复。

语音识别库自带一个静音检测用的模型文件，藏在包的 assets 目录里。
打包时如果不显式收集这个目录，运行时会报模型文件不存在。
这是打出来的包第一次运行时才暴露的，源码环境不会发现。

OpenCV 默认版本捆绑了自己的 Qt 图形库，但 OCR 只用图像处理，
不需要图形界面。换成 headless 版后省下约 160 MB，功能不受影响。

PyInstaller 不能跨平台编译。Linux 版只能在 Linux 上打，
Windows 版必须在 Windows 上打。这也是计划用 GitHub Actions
的 Windows 运行器来出 Windows 包的原因。

烧录字幕时用的临时字幕文件原本留在了输出目录里，属于清理疏漏。
是在验证发布包时发现的。现已改为用系统临时目录，跑完即删，
并补了测试防止回归。

## 六、下一步

Linux 版按计划先上传。Windows 版用 GitHub Actions 的
Windows 运行器打包，工作流已经写好，打 tag 时会同时产出
Linux 与 Windows 两个包并发布到 Releases。

Windows 版需要额外验证的点：
中文字体是否随系统可用、ffmpeg 的获取方式、
语音识别与 OCR 在 Windows 下的路径与动态库加载。
